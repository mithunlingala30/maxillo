# MaxilloAI — Flutter App

A full Flutter rebuild of the MaxilloAI Figma design: an AI-powered healthcare
app that predicts soft-tissue outcomes after maxillofacial reconstruction
surgery, using your deployed Gemini AI backend
(`https://productivityai-backend.onrender.com`).

This package contains **only the `lib/` source, `pubspec.yaml`, and
config/rule files** — Flutter's native `android/`, `ios/`, `web/` etc.
project folders are generated by the Flutter CLI itself (see Step 1) rather
than hand-written, since they must exactly match your installed Flutter/Xcode/
Android SDK toolchain versions.

---

## What's included

- **Full authentication** (Firebase Auth): email/password register & login,
  Google Sign-In, forgot-password email flow, logout, delete account.
- **Every user detail stored in a database** (Cloud Firestore): full name,
  email, age, gender, height, weight, smoking status, medical history, phone,
  notification & privacy preferences — all under `users/{uid}`.
- **Correct, editable Profile screen** wired to that same Firestore document.
- **5-step AI Prediction flow**: Patient Info → Reconstruction Details →
  Image Upload → AI Analysis → Results — matching the Figma spec.
- **Real backend integration**: the Upload step sends patient data +
  images to your `productivityai-backend.onrender.com` service and renders
  whatever it returns (confidence score, risk level, soft-tissue metrics,
  AI summary).
- **Reports / Report History** with search & filter, a rich results view, and
  an **in-app PDF viewer** (zoom, page nav, print, share).
- **Hospital-quality PDF report generation** (cover page, patient info, AI
  summary, metrics, recovery timeline, recommendations, doctor-review
  section, QR verification).
- **Recovery Tracker** with pain/swelling sliders, progress photos, and
  healing/swelling charts.
- **Notifications screen**, bottom navigation shell, onboarding, splash.

## 1. Create the Flutter project shell

You need the Flutter SDK installed locally (this code was written against
Flutter 3.24+/Dart 3.3+). Then:

```bash
flutter create maxilloai
```

Delete the generated `maxilloai/lib` folder and `pubspec.yaml`, then copy
everything from this package into that new project:

```bash
rm -rf maxilloai/lib
rm maxilloai/pubspec.yaml
cp -r lib maxilloai/
cp pubspec.yaml maxilloai/
cp -r assets maxilloai/
cp firestore.rules storage.rules maxilloai/ 2>/dev/null || true
cd maxilloai
flutter pub get
```

This gives you real, toolchain-matched `android/`, `ios/`, `web/`, etc.
folders alongside the app code from this package.

## 2. Set up Firebase (the "database" + auth backend)

The app uses **Firebase** for authentication, the user/prediction/recovery
database (Cloud Firestore), and image storage (Firebase Storage) — the
standard, production-ready combo for a Flutter app that needs "all details
of a particular user" stored reliably.

1. Create a project at <https://console.firebase.google.com>.
2. In the console, enable:
   - **Authentication** → Sign-in method → enable **Email/Password** and
     **Google**.
   - **Firestore Database** → Create database (start in production mode).
   - **Storage** → Get started.
3. Install the FlutterFire CLI and connect your app (run from inside the
   `maxilloai/` project folder created in Step 1):

   ```bash
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```

   Select your Firebase project and the platforms you want (Android/iOS/Web).
   This **overwrites** the placeholder `lib/firebase_options.dart` included
   in this package with your real project credentials, and adds
   `google-services.json` / `GoogleService-Info.plist` automatically.

4. **Google Sign-In extra step (Android):** add your debug/release SHA-1 (and
   SHA-256 for release) fingerprints to the Firebase Android app config —
   Firebase Console → Project settings → Your apps → Add fingerprint.
   (`cd android && ./gradlew signingReport` prints them.)

5. **Firestore security rules:** paste the contents of `firestore.rules`
   (included in this package) into Firebase Console → Firestore → Rules, so
   each user can only read/write their own data.

6. **Storage security rules:** paste the contents of `storage.rules` into
   Firebase Console → Storage → Rules, for the same per-user isolation.

7. **Firestore index:** the Reports screen queries
   `users/{uid}/predictions` ordered by `createdAt`. Firestore will show a
   one-click "Create Index" link in your terminal/logcat the first time this
   runs if one is needed — just click it.

### Data model created for you automatically

```
users/{uid}
  fullName, email, age, gender, heightCm, weightKg, smokingStatus,
  medicalHistory, phone, photoUrl, notificationsEnabled,
  privacyDataSharing, createdAt, updatedAt

users/{uid}/predictions/{id}
  name, age, gender, heightCm, weightKg, smokingStatus, medicalHistory,
  surgeryType, reconstructionMethod, affectedRegion, surgeryDate,
  facialImageUrl, scanImageUrl, confidenceScore, reliability, riskLevel,
  softTissueMetrics, aiSummary, recoveryEstimate, modelVersion,
  createdAt, status

users/{uid}/recoveryLogs/{id}
  milestone, painLevel, swellingLevel, recoveryPercent, photoUrl,
  notes, createdAt
```

## 3. Connect your Gemini AI prediction backend

The backend URL is already wired in `lib/config/app_config.dart`:

```dart
static const String predictionApiBaseUrl =
    'https://productivityai-backend.onrender.com';
```

The client (`lib/services/prediction_api_service.dart`) `POST`s a
multipart request to `{baseUrl}/predict` with:

- form fields for every patient/reconstruction field (`name`, `age`,
  `gender`, `height_cm`, `weight_kg`, `smoking_status`, `medical_history`,
  `surgery_type`, `reconstruction_method`, `affected_region`,
  `surgery_date`)
- file fields `facial_image` and `scan_image` (whichever were uploaded)

It then reads the JSON response and looks for (with graceful fallbacks if
a key is missing): `confidence_score`/`confidence`, `reliability`,
`risk_level`/`risk`, `soft_tissue_metrics`/`metrics`, `summary`/`ai_summary`,
`recovery_estimate`, `model_version`.

**⚠️ Important:** I was not able to inspect your backend's actual route
names or response schema directly (automated access to
`productivityai-backend.onrender.com` is blocked for crawlers), so the
client above is a best-effort, defensive integration. If your backend uses
different endpoint paths or JSON field names, open
`lib/services/prediction_api_service.dart` and adjust `_endpointPath` and
the `_normalize()` method — everything about the API contract lives in that
one file.

Also note: Render's free tier spins down when idle, so the very first
request after inactivity can take 30–60 seconds to "wake up" — the app
already uses a 90-second timeout and shows a friendly waiting message
during this.

## Project structure

```
lib/
  config/app_config.dart          # backend URL/config
  models/                         # AppUser, PredictionRecord, RecoveryLog
  providers/app_state.dart        # global auth/profile state (Provider)
  services/
    auth_service.dart             # Firebase Auth (email, Google, reset)
    user_service.dart             # Firestore user profile CRUD
    prediction_api_service.dart   # calls your Gemini backend
    prediction_service.dart       # Firestore prediction history
    recovery_service.dart         # Firestore recovery logs
    storage_service.dart          # Firebase Storage image uploads
    pdf_service.dart              # PDF medical report generation
  theme/app_theme.dart            # colors, typography, component theme
  widgets/                        # shared buttons, cards, fields
  screens/
    splash/, onboarding/, auth/, home/ (bottom-nav shell + dashboard),
    predict/ (5-step flow), reports/, recovery/, profile/, notifications/
```

## Design notes

Colors, radii, and typography mirror the Figma spec: white background,
Medical Blue `#2563EB`, Teal `#14B8A6`, Soft Grey `#F8FAFC`, dark navy→blue→
teal gradient headers, 20px rounded cards with soft shadows, Inter/Poppins
(via `google_fonts`, which downloads system-cached copies of both).

## Disclaimer

The AI prediction disclaimer from the spec ("for informational purposes
only, does not replace professional medical advice") is shown on every
Results screen and in the generated PDF, as in the original design.
